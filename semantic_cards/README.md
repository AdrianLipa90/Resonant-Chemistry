# Semantic cards

`semantic_cards/` is a first-class derived projection of the repository Source of Truth **and a calculation-state surface**. Cards are not decorative labels: downstream solvers may consume them as addressable objects carrying properties, invariants, provenance, relations, and explicit epistemic status.

## Calculation entry point

The current repository graph is loaded with:

```python
from reschem.repository_cards import load_current_card_registry
registry = load_current_card_registry()
```

A deterministic calculation context can be built with:

```python
from reschem.repository_cards import calculation_context
context = calculation_context(["MOLECULE:KrF2:SCREEN:v0.14A1"])
```

The context includes selected cards and relation targets and is canonically serialized to a SHA-256 context hash. The hash identifies the exact semantic/entity state consumed by a calculation; it is provenance, not a physical-equivalence proof.

## Coverage invariant

Every newly introduced atomic species, compound relation model, coordination/activation/topology model, compound state ensemble, molecular-state screening/admission gate, or newly addressable emergent entity must receive a semantic card or deterministic projection in the same development cycle.

Current calculation coverage includes:

- 36 canonical neutral atomic base cards from H through Kr;
- later atomic evidence as nondestructive overlays;
- model/gate cards through the current compound/molecular trajectory;
- 231 deterministic v0.1 compound-relation candidate cards;
- 27 deterministic v0.13 competing relational-state cards;
- one v0.14A1 molecular-screen model card plus nine formula-screen cards derived from the machine-readable readout.

High-cardinality candidate populations are regenerated from their frozen scientific generators instead of being manually copied into hundreds of static files. Stable checkpoints, indexes, and model/gate projections remain persisted here.

## Entity and emergence contract

A generated entity receives its own card when it becomes an addressable computational object. The card records:

- identity;
- physical/model properties;
- state invariants;
- named source artifacts;
- relations to exact card IDs or deterministic selectors;
- provenance holonomy;
- physical-holonomy status;
- emergence status;
- epistemic status;
- TIR/affective namespaces kept separate from control evidence.

Entities generated by a model are marked `MODEL_DEFINED_EMERGENT_CANDIDATE` until an independent physical admission gate says otherwise. Emergence or registry membership does **not** imply molecular existence, harmonic stability, ground-state status, electronic topology, or canon promotion.

## Relations

Relations are first-class records. A relation has a source card, predicate, target, properties, status, and source artifacts. Targets can be:

- an exact `target_card_id`; or
- a deterministic selector, e.g. `identity.symbol = Kr` and `identity.charge = 0`.

The registry can resolve relation targets and include them in a hashed calculation context. Typical predicates include `HAS_ATOMIC_COMPONENT`, `HAS_CENTRE`, `HAS_LIGAND`, `DERIVED_BY_MODEL`, and `SCREENED_STATE_CANDIDATE`.

These relations organize computation and provenance. They are not automatically identified with the physical/TIR relation operator `W_ij`.

## Holonomy contract

Two distinct concepts are kept separate.

### Provenance holonomy

Generated cards carry `provenance_holonomy` containing parent card IDs, the generating operation, and a deterministic lineage SHA-256. It answers: **through which model/state path did this entity arise?**

### Physical holonomy

`physical_holonomy` is `NOT_COMPUTED` unless winding, phase, connection, or topology observables have actually been evaluated and their source artifacts are named. A state label, graph loop, or provenance loop cannot silently become a physical holonomy claim.

Therefore:

```text
provenance_holonomy != physical_holonomy
```

## Epistemic separation

Cards preserve the source evidence status:

- physical/control fields derive only from named repository models, benchmarks, receipts, or preregistrations;
- TIR semantic axes remain `CANDIDATE_UNASSIGNED` unless an explicit mapping with provenance is supplied;
- affective mappings remain `RESERVED_UNASSIGNED` unless an explicit mapping with provenance is supplied;
- missing execution is never converted to chemical failure;
- screening results are never promoted to harmonic minima, ground-state rankings, or topology assignments without their own gates.

In particular, current v0.14A1 cards preserve `ArBr2 = MISSING_EXECUTION_NOT_CHEMICAL_FAIL`, 8/9 formulae and 40/45 starts, with no Hessian, ground-state, or geometry-only topology promotion.

## THEORY and web parity

Semantic state is not considered fully surfaced merely because Python can load the registry. The current cycle also requires:

- `THEORY/04_COMPOUND_RELATIONAL_ARCHITECTURE.md` to state the compound/molecular architecture and admission boundary;
- `THEORY/05_SEMANTIC_ENTITY_GRAPH.md` to state card/relation/holonomy semantics;
- `web/semantic_card_atlas.html` to expose the persisted semantic coverage and molecular checkpoint without inventing new semantics.

The web atlas consumes repository JSON/JSONL directly. It is a visualization layer and cannot promote any status beyond the underlying cards/benchmarks.

## Anti-drift gate

`scripts/audit_semantic_card_coverage.py` is the maintained CI enforcement surface. It checks atomic coverage, model/gate projection coverage, dynamic entity cardinalities, relation/holonomy provenance, v0.14A1 execution-state agreement, absence of silent semantic promotion, and existence/current-boundary tokens for the semantic, THEORY and web surfaces.

New model/benchmark/entity surfaces must be represented in the semantic layer and mirrored into the declared current THEORY/web surfaces before the maintained compound/molecular CI can pass.
